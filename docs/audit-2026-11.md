# Auditoria de evolução — Fyde Jarvis (2026-11)

## Objetivo

Evoluir o Fyde Jarvis existente para um assistente pessoal acessível por Android (voz e texto), com tarefas autônomas duráveis executadas no CachyOS e notificações de conclusão. Esta auditoria é baseada na leitura do branch `main` e dos PRs/branches visíveis em 2026-11-01. Não substitui testes de execução local.

## Achados prioritários

### P0 — endpoint de teste público compartilha memória

Rastreamento: [issue #11](https://github.com/deividjmoura/fyde-jarvis/issues/11), aberta para correção coordenada.

Em `apps/api/app/api/routes/agent.py`, `POST /agent/chat-test` e `POST /agent/chat-test-stream` não exigem autenticação e usam o mesmo `thread_id = "test_user_123"`. Se a API estiver exposta na internet, qualquer pessoa pode consumir o LLM e misturar contexto com todos os clientes que usam esses endpoints. O risco aumenta se tools de escrita GitHub forem habilitadas no ambiente.

**Ação antes do acesso remoto:** desativar endpoints de teste em produção ou protegê-los com um segredo de dispositivo rotacionável; criar threads isoladas por usuário/dispositivo; aplicar limites de tamanho, rate limit e timeout. Não reutilizar um segredo de teste como autenticação de produção.

### P0 — não existe ainda um canal seguro PC↔nuvem para execução remota

O `voice-client` é um cliente local que inicia requisições para a API. Os comandos existentes são poucos e baseados em padrões explícitos. Não há evidência no estado auditado de um worker persistente que receba tarefas remotas, mantenha lease, retome após reboot e reporte progresso.

**Direção recomendada:** worker local inicia conexão de saída (polling autenticado ou WebSocket autenticado), registra heartbeat, busca apenas jobs atribuídos ao dispositivo, valida cada ação contra uma política local e envia eventos de progresso. Não abrir porta de shell no notebook nem expor um daemon de comandos à internet.

### P1 — tarefas longas precisam de persistência

Não usar apenas `BackgroundTasks` do FastAPI para trabalho que pode durar minutos ou horas: roda no mesmo processo e não é uma fila durável. A documentação do FastAPI recomenda uma fila/worker separado para computação pesada ou tarefas que precisam sobreviver ao ciclo da requisição.

**Direção recomendada:** tabela PostgreSQL de jobs e eventos na primeira versão; worker local faz claim com lease, heartbeat, tentativas limitadas e idempotency key. Avaliar Celery/Redis apenas quando a escala justificar a infraestrutura adicional.

### P1 — autonomia não significa shell irrestrito

O Jarvis deve poder executar tarefas comuns sem pedir confirmação a cada passo, mas com limites definidos por política:
- Permitido automaticamente: leitura de repositórios, análise, testes, criação de branch, alterações em workspace autorizado e abertura de PR.
- Exige confirmação: merge, push em branch protegida, deploy/publicação, alteração de secrets, instalação de pacotes, operações financeiras ou ações destrutivas.
- Bloqueado: execução de texto arbitrário do LLM como shell, comandos com `sudo`, leitura de arquivos fora dos diretórios autorizados e exfiltração de credenciais.

Toda execução deve registrar solicitante, job, ferramenta, argumentos normalizados, resultado, duração e artefatos.

### P1 — app móvel e voz

A interface React existente é a base natural para uma PWA instalável no POCO. A experiência móvel precisa de:
- chat textual com streaming;
- captura de áudio no próprio Android e envio para transcrição;
- reprodução de resposta por TTS do navegador/dispositivo;
- estado de tarefas (fila, andamento, falha, conclusão);
- notificações push com consentimento e fallback visual.

O reconhecimento de voz no Android não deve depender do microfone do notebook. O cliente de voz Linux continua útil como segundo cliente.

## Arquitetura-alvo incremental

1. **API de identidade:** Firebase Auth para pessoa + credencial revogável por dispositivo; autorização por usuário e dispositivo.
2. **PWA Android:** React existente, layout responsivo, captura de áudio, texto, SSE e lista de jobs.
3. **Orquestrador:** LangGraph planeja e escolhe ferramentas registradas; não recebe acesso direto a subprocess/shell.
4. **Job store:** PostgreSQL guarda estado `queued/running/succeeded/failed/cancelled`, tentativas, lease e eventos.
5. **Worker CachyOS:** serviço systemd de usuário, conexão de saída autenticada, allowlist local de diretórios/comandos e sandbox por workspace.
6. **Notificações:** Web Push quando suportado e permitido; notificações internas no app como fallback.
7. **Observabilidade:** logs estruturados, histórico de ações, custo por tarefa, cancelamento e recuperação de jobs órfãos.

## Critérios de aceite do Jarvis autônomo v1

- O celular conversa com a mesma identidade/memória sem compartilhar threads com outros dispositivos.
- Uma tarefa submetida no Android continua mesmo após fechar o navegador ou reiniciar a API.
- O worker no CachyOS recebe tarefas sem porta pública aberta no notebook.
- O usuário vê progresso e recebe notificação de sucesso/falha.
- O worker recusa caminhos fora do workspace e comandos não permitidos.
- Nenhum endpoint de produção permite uso anônimo do LLM ou das tools.
- Toda escrita de código ocorre em branch e PR; merge/deploy requerem confirmação.
